# specs/ — 规范文档目录

> 本目录存放项目的行为规范（spec）。规范只约束「应当怎样做」，不记录「待实现功能」（待实现见根目录 `BACKLOG.md`）。

## 使用流程（每次任务开始前）

1. **负责人（owner）** 在任务开始（entry）时读本索引，按「适用场景」判定每条规范归属三清单：
   - `must_follow`：本次必须遵从（记录 id、version、适用理由）。
   - `not_applicable`：本次不适用（记录排除理由，可按类别合并）。
   - `uncertain`：无法判断（记录疑点、受影响步骤、下一步查证动作）。
2. 只读 `must_follow` 的正文，不必遍历全部正文。
3. 把三清单写进每个任务的 `instruction` 传递给协作者（含 id、version、路径、关键条款、待澄清项）。
4. **场景变化**（任务拆分、用户改需求、进入新阶段）时重新判定；协作者发现遗漏也必须提出。
5. **交付**：协作者给出关键条款对应的结果/证据；负责人逐项检查，最终披露未满足项与保留异议。

## 判定规则

- 「不适用」不等于负责人有权豁免：须依据规范的 `applies_to`/`not_applies_to` 并记录理由；用户明确要求使用的规范不能排除。
- 无法判断时：先读该规范适用条款；仍不清楚则标记具体疑点。影响下一步正确性或不可逆操作时，先解决再执行；不依赖该疑点的工作继续。
- 规范冲突时，不能用自填的 `priority` 数字压过其他指令，应回到负责人/用户裁决。
