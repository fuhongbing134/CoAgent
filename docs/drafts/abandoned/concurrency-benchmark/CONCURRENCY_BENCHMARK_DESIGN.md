## 1. 用户基线与验收范围

用户已授权分支、三端讨论、文档和实际测试；没有指定性能SLO、费用上限或必须达到的并发容量。目标是验证当前真实存在的广播、跨对话、跨Agent和消息桥混写，得到可重复的正确性证据与性能基线。顺序为讨论→设计落盘与复核→实施→运行→证据复核。当前阶段符合该基线；实际容量未验证。

第一轮保留真实SQLite、事务、HTTP及调度路径，在独立进程中注入脚本worker，禁止真实模型调用；不是只压一个自制SQL循环。真实CLI另列有限验证阶段。非目标：新增生产并发调度、实现6B解除/自动恢复、启用统一generation、证明任意外部SQL/Job外写入者安全、证明源文件并发编辑安全、得出模型账单或跨机器通用容量。

正确性验收为各场景明确不变量零违规且试验有效；零违规仅适用于已执行的次数和条件，不证明所有调度。性能阶段产出基线，不预设毫秒门槛，也不以低延迟掩盖失败。硬件容量、真实CLI安全和费用不得从模拟结果外推。

## 2. 事实基础与复用

- `web_chat.py` 使用ThreadingHTTPServer并逐收件人起worker；同agent同conversation有HTTP pending/活动检查和ExecutionTracker事务认领，HTTP 202只表示接受，不证明后续认领成功。
- `collaboration_service.py` 的job锁防重复驱动，ready[0]保守串行；`web_chat.py`协作invoke另有每Agent锁，普通跨对话worker不共用该锁。
- `execution_tracking.py` 用BEGIN IMMEDIATE、域owner及fence条件更新；默认resolver为None，走legacy可见session冲突检查。历史P9窗口和P10全历史扫描风险仍存在，不写成全覆盖或已实测性能问题。
- 网页与`agent_bridge.py`写同一SQLite文件的不同业务表。WAL允许读写重叠但仍单写事务；常规写连接timeout=10。迁移屏障协调迁移，不是普通业务全局互斥锁。
- 复用`test_execution_tracking.py`的Barrier/回滚/旧token，`test_execution_wiring.py`的临时库和取消，`test_direct_answer.py`脚本协议，`test_capabilities.py`和`test_collaboration_actions.py`本机HTTP，`test_grok_adaptation.py`隔离消息桥。`test_concurrency_backend.py`绕过宿主验证真实CLI新session重叠，不能作为工作台容量工具。

## 3. 分层与隔离

L1数据层：真实事务、域竞争、共享可见session及回滚。L2宿主层：真实HTTP/worker/协作接收，脚本执行替代模型。L3进程层：有限无模型子进程验证启动/取消/退出证据。L4真实CLI：后续单独运行与报告。MCP首轮直接调用工具函数只证明桥接写库层；完整stdio客户端及多桥接进程不计为已覆盖。

每个执行进程必须显式接收新建证据根目录，DB由工具在该目录独占创建，不接受任意现有DB路径；校验规范绝对路径、拒绝符号链接/重解析路径和硬链接异常，确保不是项目默认DB及环境指定运行DB。不读取运行DB内容，不复制它作种子。清除子进程继承的DB路径配置并显式注入隔离路径；web与bridge指向同一隔离库。调用前校验，异常立即停止。端口使用127.0.0.1:0，不连接现有工作台；走正常startup_server实例锁、初始化和请求安全校验，不关闭认证以求方便。

每个场景独立进程/数据库，避免全局registry、service单例、patch和身份相互污染。C14重启、C17实例锁例外：多个测试进程明确共用同一新建隔离库。桥接身份固定在独立进程或固定实例中，不在线程间竞争修改模块AGENT_ID。脚本后端合法输出关联的唯一任务标记，拒绝任何真实CLI启动；注入只在测试进程生效，不修改生产锁序或放宽数据库超时。

## 4. 正确性矩阵

通用同步：Barrier对齐竞争，Event保持胜者或并发worker，控制器观察达成条件再释放；禁止仅sleep猜测。每组记录提交、域认领、worker进入/退出、锁等待/获锁/释放、写入、终态及域释放。正确性与性能样本分开。

| ID | 场景与构造 | 通过条件与边界 |
|---|---|---|
| C1 | 同域两HTTP提交，胜者驻留 | 持有期间至多一个成功认领/启动；胜者已占用后第二次提交必须409；自然同步竞争另按C2记录；逐请求追踪后续结果，不以202数代替认领 |
| C2 | 分别测试自然HTTP竞争和测试注入的重复派发 | 自然双202是待查假设，未复现不能判漏洞；注入标明非自然流量。即使两接受，第二域认领不能接管原owner；失败清理不得释放他人域 |
| C3 | 同Agent不同对话普通worker | 证明两执行区间重叠且对话/消息/run对应正确，不只观察两reserved记录 |
| C4 | 同对话不同Agent | 两域可重叠，无全对话串行化或串写 |
| C5 | 广播三端脚本worker，另测缺Grok | 单请求对应实际收件人集合，子任务各自终态；正常三端证明重叠；缺Grok按当前路由缩减，不要求不存在的三域 |
| C6 | 同job两个ready任务，重复kick | 任意时刻至多一个任务实际执行；派发及协议接收后再推进。已有reserved时再次reserve应拒绝，作为附加断言，不能代替执行区间判据 |
| C7 | 同Agent两个协作job/对话 | 第二开始等待可早于第一释放，第二获锁须不早于第一释放；实际worker区间不重叠。仅有排队不是DomainBusy |
| C8 | 普通HTTP与协作抢同域 | loser不启动、不接管；原owner/fence不被失败清理改变，双方角色和状态正确 |
| C9 | 网页消息与桥登记/发送/已读混写 | 对已确认成功操作按唯一ID核对内容及次数，不丢失、不半写；不要求回调顺序等同ID顺序，ID可有间隙 |
| C10 | 启动前取消、启动竞争、启动后取消 | 启动前无launch；取消意图不等于退出；confirmed或not_started才可释放；unknown保持quiescing，不强清 |
| C11 | 已结束旧run的延迟回调遇到新owner | 旧token写入被拒，新owner/fence/消息不变；同时检验宿主接收链，不只tracker单元方法 |
| C12 | 同message/call顺序及并发重复调用 | 不重放脚本worker；原回复接收幂等，任务/预算不重复记账 |
| C13 | 两对话预置相同非空legacy绑定 | 保持首个选择后的执行占用再放行第二个选择；第二域先成功认领再因可见session冲突拒绝，必须不launch、以not_started释放回idle，第一owner/fence不变。分类为session冲突而非HTTP409；新ID未公布窗口未覆盖，不开启resolver替代默认路径 |
| C14 | 新实例重启及控制状态初始化 | 旧pending转cancelled，遗留reserved/quiescing不被当成已退出；新准入仍拒绝。函数级初始化与真实独立进程重启分列，不冒充崩溃恢复 |
| C15 | 独立连接获写锁，握手后请求；短持有与超过10s两组 | 短等待成功或可解释结果；长持有产生锁超时/错误桶，不误记409。记录实际超时而非要求恰好10s；不需要open-loop才能触发 |
| C16 | 大量历史+非空绑定下重跑C1/C13 | 正确性不变量仍成立；变慢/超时与状态错误分开 |
| C17 | 第二服务实例争同隔离DB | 正常实例锁拒绝，不破坏首实例；小用例不当容量主轴 |

C1-C13与C16默认100组，重启C14为20组，C15短/长各3组，C17为3组；这是覆盖预算，不是概率保证。首个违规即停止后续负载，保留有效失败。同步未达成、无预期重叠或超时卡在测试屏障标invalid，不算通过或系统容量失败。

## 5. 性能工作负载与数据

先一次20请求冒烟核对工具，后跑性能；冒烟不是正式样本。正常闭环每客户端等关联任务终态再提交，客户端数为1/2/4/8，独立域池避免正常负载被预期同域忙碌淹没。广播按每请求实际子任务数记录；协作同Agent锁作为独立排队场景，不把其吞吐外推普通worker。

主矩阵：普通跨对话负载，客户端4档×历史run三档(0/1000/10000)，脚本驻留50ms。每组合预热100请求，正式1000请求，重复3轮，合计36000正式请求。跨Agent、广播、网页与桥1:1混写、协作排队各作客户端1/4/8、历史1000的锚点，复用相同预热/采样/轮次；混写1000操作总数而非每种各1000，桥登记在预热前完成。驻留0ms是额外基准对照，仅主路径历史1000、并发1/8两点，避免组合爆炸。0ms可以测固定开销，但不能证明执行重叠；50ms也不保证重叠，必须测量。驻留不在写事务内，不通过长期持DB锁伪造真实模型工作。

历史生成只用合法已结束run及关联域/会话，非空legacy绑定必须存在且唯一；全新空session无法有效触发P10扫描。历史0指预置run数为0，不要求绑定或schema也为空。主矩阵固定100个绑定对话和消息总量/长度，历史run分散到这些对话，记录精确分布。补充单变量：历史1000、并发4，绑定数1/100/1000；消息数0/1000/10000且每条固定256字符。各点1000正式请求×3轮。共享session作为正确性异常不混正常分布。

每轮从同一逻辑种子新生成DB；性能运行产生的run增长记录初末数量，不声称整轮历史恒定。轮次顺序使用固定随机种子打乱，记录冷启动初始化耗时单独一列；预热后性能称暖态，不声称清除OS磁盘缓存。主矩阵为探索基线，若运行时间上限触发则按部分矩阵报告，不自动缩样后宣称完整。

## 6. 时间、并发及统计口径

使用monotonic_ns记录同机事件；UTC仅用于定位。同进程为主，跨进程须记录计时域并校验可比性，不直接相减来源不明的时间戳。

- N_client为配置客户端数及瞬时未完成请求数，提交累计量另名submitted；N_domain为瞬时reserved/running域数；N_exec为实际worker/子进程执行区间重叠数；N_wait为等待协作锁数量。quiescing单列占用，不计执行。不得将reserved_at→released_at称实际CLI执行区间。
- t_send→t_response是HTTP接受/拒绝响应延迟，202/409/503/其他分桶；t_begin_call→t_domain_acquired是worker域认领延迟，不能互称准入。
- t_lock_wait→t_lock_acquired是协作锁等待；无该锁的普通worker填N/A。超时或取消等待记录观测时长，无成功获锁时间。
- t_worker_enter→t_worker_exit是脚本worker耗时；t_process_start→t_process_exit仅进程层存在。协议接收/提交与域释放另打点；t_send→t_terminal_commit为用户业务完成，t_send→t_domain_release为资源释放，两者可能不同。
- 客户端轮询观察终态另记t_terminal_observed、轮询周期和延迟上界；不把轮询开销无说明当提交耗时。正常负载轮询固定20ms，报告请求量；必要精细时由测试进程观察提交事件，不新增生产API。
- 广播请求终态取关联子任务全部终态；部分失败仍为请求失败，记录每子任务结果。成功吞吐、全部终态吞吐分别为窗口内对应数量/窗口秒；另报到达率及排空时间，预热、初始化和排空不混测量窗口。延迟按发出于正式窗口的队列追踪至30s截止，避免漏掉跨窗口完成请求。
- 忙碌拒绝率=HTTP忙碌拒绝/有效HTTP提交；域认领拒绝率=DomainBusy/域认领尝试；协议拒收率=拒收回复/实际接收尝试；数据库异常率=失败逻辑操作/对应逻辑操作尝试，web/bridge分别报。内部事务尝试和重试是另表，不能混分母。预算/权限/参数错误独立分桶，零分母填N/A。
- 全部样本保留结果。成功延迟分布明确条件为成功；失败延迟也报告；客户端超时/未完成保留观测时长、截止与右删失标记，不填0、不删除、不把30s当精确完成时间。HTTP拒绝无完成延迟。连接超时后继续追踪隔离宿主结果，避免误认未执行。
- 每轮分开计算nearest-rank分位数：排序后第ceil(p*n)个（p∈(0,1]，p99使用p=0.99，空样本为N/A），单位ms，附n/min/max/错误/未完成及轮间范围。不平均三轮p99，不合并不同状态或场景后称单一p99。1000甚至5000样本都不自动构成验收级p99；需另定精度/置信要求及相关性方法，本轮仅探索，不编造置信区间。

## 7. 注入、校验、停止与清理

测试侧包装观察锁与调用，保持原锁委托、异常和释放语义；不能为采样改生产锁序(state_lock→Execution.lock→MigrationBarrier→SQLite)。正确性用详细事件，性能用每请求最少事件及内存缓冲批量落JSONL，不边持数据库写锁边写日志。每档记录采样开/关对照100请求的墙钟开销（不作容量样本），过大时披露并减少非必要观察，不能删核心正确性检查。

注入包括预约/释放触发器abort、写锁持有、取消vs启动、模拟unknown、旧token、重复接收。模拟unknown只证明宿主状态处理，L3真实子进程另证明实际取消退出。跨崩溃自动恢复没有验收对象；可测取消响应/确认退出/重启就绪耗时，但分别命名，不称自动恢复耗时。

立即停止：双域owner/重复launch、旧fence写赢、cancelled被错误覆盖、unknown误释放、对话串写、已确认写入丢失、目标路径不符、发现真实CLI或凭据访问。请求30s截止、单场景15分钟、全次2小时；健康检查失败或线程不退出停止升档。限时属于工具预算，非SLO。长锁实验需给>10s持有及清理时间，不缩短生产超时使其快过。

finally释放测试Event、关闭HTTP、限时join、终止本次明确记录的子进程并确认退出，不按名称杀其他进程。资源未知保留证据目录并报告，不强改域idle，不自动删除失败DB。可做隔离DB的integrity_check/foreign_key_check及按request_id核对，不读取运行DB。性能每轮后检查不变量，失败即标该轮不可作为正常容量结论。

## 8. 真实后端与成本边界

先完成无模型阶段。真实阶段提案为每个可用后端最多2次新session探针加1次恢复/取消探针，至多9次CLI进程调用、每次120s；CLI内可能多轮模型调用，所以9次不是9次计费请求，也不是金额上限。实施前须提供实际模型/计费方式和可执行费用上限；若无法限制或估算，向用户提交具体预算选项并保持真实阶段待运行，其他层继续。不读取凭据内容，不因既有登录擅自无限消费。真实阶段隔离工作区/session，确认清理范围，不做高并发性能宣称。实际token/费用有权威usage才记录，否则unknown，墙钟时间不能冒充成本。

## 9. 证据与报告格式
