## 用户基线

用户提出：架构图及其说明、执行流程图及其说明都是对当前代码的描述；代码修改后目前没有约束把修改同步到这些图上。希望实现「代码修改并合入对应分支后，相关图片、描述随之调整」。

## 三端讨论结论（entry-2927，已收敛）

- 主控制点放在**合入前**影响判断，合入后仅作遗漏补正；不引入合入后自动重写图文或为此搭 CI。
- 触发条件窄化：只有改动「文档已陈述的事实」（职责边界、调用顺序、状态转换、接口、持久化关系、权限、配置行为）才要求同步；纯重构、测试、历史原稿、未实施提案、单纯行号漂移可说明理由后不改图。函数改名/路径移动需复核源码引用。
- 责任链：author 提交「文档/图文影响结论」，reviewer 核对图文与代码一致，合入执行者确认实际合入版本包含已审核更新。
- 分支版本：覆盖每次合入的目标分支；跨分支合入、回移、冲突解决后重新评估。
- 阻塞分级：错误现状描述为阻塞合入项，严重级别按影响判断，不一律标为最高级（P0）。
- 自动化边界：形式检查（链接可达、图源解析/渲染）与语义核对（图文是否等于代码行为）证据分离，不把形式通过写成语义已同步；语义由 author 与 reviewer 承担。
- 义务落点：触发动作放 code-review-spec；事实一致性原则 document-management-spec §2 已有，不重复新增。
