## 3. 候选和决策

### 3.1 候选

| 选项 | 内容 | 取舍 |
|---|---|---|
| A：原样采用固定七步顺序和固定 2–3 个候选 | 七个标题作为单向硬流程，所有方案都提供规定数量候选 | 不采纳。会强迫无真实取舍的小修改凑候选，并可能要求对每个候选做完架构和详细设计才选型；与现行规范不虚构备选、按风险裁剪的要求不符。 |
| B：仅保留现状规范，不增加流程结构 | 继续使用既有设计记录字段，不作流程化表达 | 不采纳。无法响应用户明确提出的流程化改进目标。 |
| C：把七步转为可回退、按风险裁剪的阶段检查点，嵌入现有规范 | 记录需求基线及现状；仅在有真实取舍时列候选并用共同验收判据比较；有足够依据时初选，深化后允许回到候选/取舍；对选定方案展开适用的架构、接口及详细设计；记录验证计划及必要的引入/迁移/回退方案；评审并区分文档、方案、实施和验证状态 | **选定。** 同时保留七步的可定位结构和轻重裁剪，不把步骤次序锁成不可回退瀑布。 |

选择 C 的依据：符合设计规范 §2.1 的基线对齐要求、§4.5—§4.6 的有据取舍与不虚构备选、§4.1 的风险裁剪、§4.8 的实施后结果更新，以及 §5 的状态区分。深化设计可能提供新的比较证据，所以既不能要求每个候选全量设计后再选，也不能在毫无比较依据时作终选。

### 3.2 已确认的设计约束

- 候选数不设固定下限。有真实取舍时记录实际候选及排除理由；其优缺点使用同一组需求/验收判据比较。无真实备选时说明理由，不硬凑。
- 流程采用阶段检查点而非单向流水线：现状和基线 → 轻量候选比较与初选 → 对选定方案深化架构、接口及按风险裁剪的详细设计；深化暴露问题时可回到候选或取舍。验证计划无法覆盖关键验收时，可返回设计取舍或需求澄清。
- 设计须显式记录对有效需求基线“符合／偏离／未验证”及依据。三问中的理由、代价和验证不能替代该状态；需求分析的三问与设计问题分属不同产物。
- 验证阶段记录的是验证计划、验收方法和必要时的迁移/回退安排；实施后的实际验证结果、证据和缺口在后续更新，不把计划写成结果。回退要求按实际引入、迁移或切换风险适用。
- 按风险裁剪图示、详细设计和回退内容；图示不能替代契约，须与接口、拒绝/取消/失败路径及证据边界一致。仅展开影响本次正确性、取舍、实施或验证的维度。
- 未决项按能否独立判定成败拆分冻结；阻断相关步骤的未知先查证或澄清，不依赖它的部分可继续。文档已决定、方案已决定、已实现、已验证须分开表述。
- 每个阶段应给出与任务规模相称的进入、退出及回退条件；具体简洁措辞由正式规范修订稿落实，不能引入固定会签或额外审批门槛。

## 4. 独立评议及回应

### 4.1 DeepSeek Harness 独立评议

DeepSeek 先独立阅读设计规范 1.4.1 并逐项评议七步和三问。认为整体方向正确，但指出初始顺序可能误导为对每个候选做全量设计后才选择；三问未显式呈现需求基线对齐；缺少进入/退出和回退边。另指出候选数不可硬定、验证计划与实测结果必须分开、图示不可代替契约，设计应按风险裁剪并嵌入现有规范。此处保留其初始“选型前置”的意见作为讨论历史，最终顺序以双方回应后确认的迭代表述为准。

### 4.2 Grok 独立评议

Grok 基于原提议独立检查设计规范及需求规范相关条款。支持七步和三问作为现有设计规范的流程化展开，但反对硬流水线。其具体建议包括：候选数量不固定且按共同判据比较；轻量比较后初选、深化后可回退重选；需求基线符合/偏离/未验证显式呈现；验证计划与实施后结果分开；图、详细设计、回滚按风险裁剪；未知按独立判定成败粒度冻结；实施后结果按 §4.8 更新。并建议保留阶段进入/退出/回退条件，需求三问与设计问题不混为一体。

### 4.3 逐点回应与分歧处理

DeepSeek 对 Grok 的六个重点逐点回应：选型顺序、候选数量与共同判据、需求基线状态、验证计划与结果、风险裁剪/阶段边界、嵌入现有规范。六点全部接受，无实质分歧；DeepSeek 明确以“轻量比较→初选→深化→必要时回退”的迭代表述替代其初始略绝对的“选型前置”，并接受未知项按独立成败判据拆分及实施后结果后续更新。双方确认需求分析问题由需求基线承载，设计问题消费该基线。
