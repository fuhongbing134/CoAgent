# 用户期望对齐规范增强

文档状态：已决定；方案状态：已实施、静态检查通过，待非作者审核。作者 Codex；非作者审核由 Grok 承担，交付与 Git 操作由负责人及宿主安排。

## 背景、目标与范围

用户原始要求（entry-2376）：在编码、review、设计方案及后续修复 bug 的每一步，必须确认用户原始问题或期望场景，保证没有偏离。预期结果是 Agent 能指出正在解决谁的什么问题、用户希望什么结果，并用检查证据判断方案和实现是否仍满足它。仅完成技术改动或通过测试不能代替满足用户期望。

确认依据是本轮用户明确要求与获授权的任务 instruction；本轮没有实质歧义，无需再次询问。验收：两份规范包含基线、阶段复核、纠偏和 reviewer 结论；版本与索引一致，无产品代码或协议改动。

## 决定与理由

- 在 CODE_REVIEW_SPEC 第 4 节定义编码任务基线及每步核对，第 7 节请求模板携带基线，第 8 节要求独立 reviewer 检查用户场景并明示结论。版本 1.0.0 → 1.1.0。
- 在 DESIGN_DECISION_RECORD_SPEC 新增第 2.1 节定义设计期望基线和持续复核，第 4 节背景与目标记录该基线，责任节要求交付对齐结论。版本 1.1.0 → 1.2.0。
- 基线保留用户来源、原始问题、使用场景、期望结果、范围及验收判据；推断和未确认项独立标明。确认可依据已有明确要求与授权，重要歧义才询问，避免每一步都等待重复批准。
- 复用 instruction、设计文档、自查、review 与 handoff 记录，允许引用；以每个有意义工作步骤和阶段变化为复核点，不要求逐命令写日志。目标或验收改变必须由用户确认，负责人或 Agent 的内部共识不能替代。
- 不改 AGENT_DISCUSSION_SPEC：其第 6 节已要求全过程核对目标/范围并及时纠偏，本次两份规范补齐具体基线和 reviewer 证据，不重复建立规则。该规范已读；独立编写阶段不适用其多 Agent 讨论流程。code-review-spec v1.0.0 与 design-decision-record-spec v1.1.0 为本次 must_follow；三清单无剩余 uncertain。

未采用每步强制向用户提问、增加协议字段或自动拦截器：会增加等待且不能证明理解正确；也未仅写“不偏离”口号，因为缺少基线与纠偏动作无法检查。规则执行仍依赖 Agent 与非作者实际审核，文档修改本身不能保证未来任务执行有效。
