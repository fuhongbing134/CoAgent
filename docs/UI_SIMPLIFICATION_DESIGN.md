## 2. 背景与目标

现有左侧展示 Agent 的厂商、模型、角色、活动时间和能力信息，以及工作台环境检测卡片；协作任务位于消息列表上方，用户难以持续发现任务。顶部目录面板还占用消息区域。

目标：左侧以任务为主，品牌下方用小卡片仅显示可用 Agent 名称；移除详细 Agent、环境检测及顶部目录 UI，扩大消息区。保留发送、刷新、任务操作和后端设置功能，避免仅删除 HTML 导致空节点错误或测试失效。

## 3. 范围与约束

本次实施范围拟为 `web_chat.py` 的 PAGE 布局、CSS、页面脚本，`collaboration_ui.js` 的挂载与展示状态保留，以及相关前端测试适配；如需更改后端行为，应先说明偏离并重新决定。

- 保留 `/api/settings`、`save_working_directory`、`resolve_working_directory`、目录校验及会话保护。已保存对话继续使用原目录，未设置时才使用 PROJECT_DIR；不清设置、不静默回退。用户已接受取消页面入口，目录失效时仍可由现有后端路径修正。
- 保留 `/api/agents`、`cli_availability`、后端 probe、鉴权及检测测试；不删除消息桥的登记与通信接口。
- 保持消息发送、收件人规则、任务请求和任务操作接口不变；不改协议、数据库结构或历史任务。
- **停止功能细化不在本设计范围**：本轮不调整停止按钮阶段规则、退出确认、stopped/quiescing 映射或恢复入口。布局完成后另行细化；已知 failed 按钮问题不因本设计而关闭。
- 用户报告前批改动已按命令提交，本轮未执行 Git 核实；提交保存与合入批准分别判断，不沿用为本 UI 的验证证据。

## 4. 五条设计边界

### 4.1 可用名单与发送规则一致

品牌「Agent 工作台」下方放一个小卡片，仅展示支持且满足当前启动条件的 Agent 名称。展示和 `renderRecipients()` 共用同一可用性判断，复用 `/api/agents` 的响应，不另建平行规则：

- Codex：当前规则检查 `codex_cli_available`。
- DeepSeek Harness：检查 `dsh_cli_available`，且登记列表存在 `deepseek-harness`。
- 不把任意登记对象都当成工作台可调用后端；无可用项显示简短空状态。
- 「可运行」仅指满足现有启动条件，不保证认证、网络和实际执行成功。名单更新不改变 @ 提及和发送的既有语义。

可复用 `#agents` 作为小名单容器，但重写 `renderAgents()`，清理详细卡片及能力插槽专属字段、Map 和样式；不要残留对已删除模型等节点的访问。

### 4.2 目录面板与专属前端依赖完整删除

删除 workspace-panel、workspace-path、save-workspace、状态文字及专属样式；同时删除节点引用、加载保存函数、按钮与回车事件、启动及会话切换中的调用、专属版本和保存状态变量，以及 `refreshRound()` 中禁用目录输入的 busy 逻辑。共享刷新版本、活动运行数据及停止按钮仍有用途，不能连带删除。

`main` 从四行改为三行：顶部栏 `auto`、消息区 `minmax(0,1fr)`、输入区 `auto`。核对错误提示的所属容器或明确网格定位，避免错误出现时产生额外隐式行、挤掉输入区。保留 min-height:0、消息滚动及输入区域可见性。

### 4.3 环境展示与页面探测轮询删除，后端保留

删除工作台环境卡片、探测按钮事件、`refreshCapabilities()`、专属变量和样式，以及页面对 `/api/capabilities`、`/api/capabilities/probe` 的调用。清理刷新中的能力错误展示分支，不保留只为访问已删除节点而存在的空壳函数。

仍刷新 `/api/agents`、会话、活动运行、任务及消息；保留刷新去重、合并和过期响应检查。后端 probe 不再由页面触发或轮询，但接口、鉴权及检测行为保持原样。能力探测与发送所需 CLI 可用性是不同链路；任务操作仍用到 capability token，不能误删共享 token。

### 4.4 协作任务区迁到侧栏固定容器

顺序为 **品牌 → 小 Agent 卡片 → 当前对话任务**。将 `collaborationRoot` 挂到侧栏固定容器，移除 `messagesNode.before()`；不复制两套任务 DOM，不改变任务 API、操作请求与停止语义。

- 侧栏独立滚动；任务需求与长指令保留折叠详情，状态、原因和操作可见。
- 轮询保留任务区与卡片详情展开状态、用户输入及侧栏滚动位置，避免每次 replaceChildren 造成交互丢失。已有草稿按 job 隔离；跨会话保留时也不得显示到其他 job。
- 会话切换立即清除旧任务展示或使其不可操作，重置对应渲染签名；以会话标识和刷新版本拒绝迟到响应，覆盖 A→B→A。不能只靠响应回来后再替换旧卡片。
- 任务展示继续使用安全文本写入，不把 Agent 或用户内容转为未转义 HTML。

### 4.5 窄屏可展开任务区

≤760px 时侧栏位于顶部，提供「任务（数量）」展开入口，初始默认收起；用户展开后轮询不能重置其选择。展开内容限高并内部滚动，按钮换行、输入控件适配窄宽，长需求不撑宽页面。不能直接将完整卡片塞进原 190px 限高而不检查实际可操作性；聊天消息和输入区域须保持可用。

## 5. 决策理由与未采纳方向

| 方向 | 决定及理由 |
|---|---|
| 保留或折叠详细 Agent、环境卡片 | 前轮提出过；用户明确选择取消，改为仅名称小卡片，释放任务空间 |
| 只删 HTML、隐藏 DOM 或保留空壳 | 不采用；旧节点事件和刷新访问会报错，隐藏方式也不满足取消无用界面的目标 |
| 删除目录或检测后端 | 不采用；用户选择只删 UI，目录仍决定执行及会话身份，后端检测可独立保留 |
| 小名单只看 CLI 找到 | 不采用；与 DeepSeek 现有登记前置条件不一致，应复用发送规则 |
| 任务继续放消息列表上方 | 不采用；用户希望一眼发现任务，侧栏已有独立滚动区域可复用 |
| 一并修停止状态机与按钮 | 暂缓；用户要求先完成本次布局简化，再细化停止，避免扩大审核范围 |

## 6. 六项测试同步要求

以下是实施后的要求，不是本轮通过结果。

1. **启动边界**：`test_frontend.cjs:21` 当前用最后一次 `loadWorkspaceSettings();` 截断启动代码；改为明确、稳定的启动边界并断言存在，找不到时明确失败，不能静默 slice 到错误位置。覆盖完整定义与事件初始化，避免为测试漏执行页面代码。
2. **名单断言**：旧详细 Agent 卡片与能力插槽断言替换为名单与发送规则一致、不可用项排除、空状态及可用性更新；覆盖 DeepSeek CLI 存在但未登记、已登记但 CLI 不存在等组合，不削弱原发送保护。
3. **能力展示与后端测试分开**：被移除的能力展示失败隔离断言可删除；后端 probe、接口鉴权及检测测试保留。验证新页面不再请求能力探测或目录设置 UI 数据，而发送所需 `/api/agents` 仍正常读取。
4. **刷新和任务交互保护**：保留周期刷新去重、手动刷新合并、A→B→A 过期响应隔离；增加任务区响应隔离、侧栏挂载、展开状态、草稿输入及滚动保留检查。切换后旧卡片不能继续操作，新对话任务正常加载。
5. **页面脚本提取**：`test_capabilities.py:19` 从 PAGE 提取内联脚本；保持单一 script 结构时可沿用，核对完整脚本执行。如改变结构须同步提取方式，不能只测试一个无初始化片段。
6. **真实缺失节点行为**：DOM mock 预置实际必需节点，对未定义 ID 返回 null，避免自动创建任意 ID 掩盖残留引用；补齐新布局实际用到的 DOM 行为，不用占位节点伪造已删除界面。视觉布局另由浏览器验收。

实施时按改动运行前端脚本回归、`test_capabilities` 的后端测试及相关目录、发送、协作回归，再按需要运行全套；记录被测版本、命令、结果及跳过原因。浏览器验收至少覆盖桌面、≤760px、长文本、多任务、错误提示、会话切换和输入区可用性。模拟通过不替代浏览器检查。
