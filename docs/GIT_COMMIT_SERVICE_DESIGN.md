### entry-2183 工作台接入决定与配置边界

采用独立 stdio MCP 适配器 `git_workbench.py`，复用已安装依赖，不新增 HTTP 服务。宿主分别为三个客户端配置固定 executor；该启动配置不是防恶意进程的凭证体系。执行在正常授予权限的 MCP 进程中，不提权、不启动越过沙箱的 helper；在只读环境启动仍然只读。

宿主在仓库外提供 JSON 任务绑定、只读 approval 目录和可写 operation 目录。作者及目录从生产 collab_tasks、collab_bindings、workbench_conversation_settings 只读查询；配置明确 job_id、task_id、directory、branch、base_commit、remote、executors。没有显式目录、任务已停止、目录改变、执行者未获安排都拒绝。数据库本身沿用现有位置，配置和审核状态必须在任务仓库外。

批准由宿主/reviewer 在实际审核后保存；工具没有批准或任务注册入口，不从自由文本猜审核通过。执行仅保存独立 operation，不能覆盖 approval。宿主必须用 OS ACL 保护配置和批准文件，不能把客户端自设参数当可信身份。单功能独占仍由宿主安排；不实现锁。

未采用在消息桥里直接扩大 Git 写权限的方式。只暴露 create_branch/commit_and_push；配置和批准格式见 MCP_SETUP.md。本次不修改用户配置、不访问生产数据库、不验证真实权限；MCP 客户端实际连接待配置后验收。

## 2. 背景与目标

目标流程：**一个功能 → 文档与功能分支 → 编码 → 非作者 review 通过 → Agent commit + push 到对应功能分支。** Git 工具不检查设计文档是否存在，文档要求由功能流程承担。

首期提供建功能分支并切换，以及审核后的提交和普通功能分支 push。合入 main 是独立动作，只有用户明确提出才允许；merge_to_main 不进首期。明确排除 push main、force push、删除分支，不提供任意 shell、自动 reset、清理或丢弃改动的入口。

串行锁、worktree 和通用凭证体系留后，不作为首期必做。review 内容核对和失败结果区分保留为小检查，不恢复原完整平台。

## 3. 实现形态与权限边界

`Agent → 共用工具入口 → 一个共用 Git 模块 → Git`

模块内部通过受控参数执行 Git，不由三个 Agent 分别拼装三套逻辑；不建设独立 HTTP 服务或通用权限平台。需要 MCP 接入时可以增加薄适配。

哪个运行环境具有正常授予的 .git 写权限，就在那里运行模块。当前 Codex 会话的 .git 只读，需要配置有权限的执行入口；换脚本或工具不能绕过限制，也不能推广为所有 Agent 的权限事实。实际接入、写权限与远端认证都需验证。

任务上下文确定仓库、目录、分支与允许执行者；参数里的 agent_id 不作为授权依据。首期复用明确任务安排和 reviewer 记录，不另建通用凭证体系。远端认证沿用执行环境已有配置，日志和结果不暴露凭据。

## 4. 首期使用前提

**同一时间一个功能独占当前工作区，靠调度安排，不实现锁。** 这是使用前提，不代表现有调度器已经保证；实施接入时需落实。其他功能同时写入时停止并报告，不宣称支持并发。

建分支前确认工作区适合切换；提交前核对当前仓库、分支、基线及受检内容。用户手工 Git 或编辑改变状态时重新核对，不沿用旧结论。不自动 stash、不清空他人暂存、不覆盖改动。

## 5. 最小接口契约

| 接口 | 语义 |
|---|---|
| create_branch(task_id, name) | 从任务记录明确的基线创建并切换功能分支，返回基线、实际分支和 HEAD；名称不能是 main，重名报错不重置，工作区不适合切换时拒绝，不丢弃或藏起改动。 |
| commit_and_push(task_id, branch, files, message) | 前提为有效非作者 review 通过且拟提交内容仍一致。按显式文件清单提交，向固定已有远端的同名功能分支普通 push；结果分阶段返回 commit_id、push_status 及错误说明。 |
| merge_to_main(...)（后续独立能力） | 不进首期实现；将来仍须用户明确的合入请求与有效非作者审核，不能从普通功能任务或 Agent 转述推导许可。 |

所有接口带 task_id，通过任务上下文解析仓库、目录、分支基线及远端，不接收任意仓库路径或 push URL。files 是仓库内显式字面路径，不允许越界或 Git 元数据路径；提交信息非空，Git 参数不拼成 shell 字符串。

commit_and_push 是便利操作，不承诺本地提交与网络推送原子完成。提交已成功而 push 失败时保留并返回 commit_id，只重试推送该提交；超时、响应丢失或结果不明时先查询本地提交与远端目标，再决定下一步，不盲重试、不强推。

## 6. 五个小检查与失败处理

1. **review 绑定受检内容**：通过记录关联任务、分支、基线、非作者 reviewer、受检文件及差异；不能只有 review_passed=true，也不能由作者自填。提交前核对拟提交内容未变，变化就补 review。提交成功后确认实际提交对应受检内容，将 commit_id 写回同一记录；写回失败说明已提交事实，不再重复提交。
2. **commit 与 push 结果分开**：区分尚未提交、已提交未推送、推送成功和结果待核实。push 失败只补推原提交，非零退出或超时不自动等同“没有提交”。保留现场，不自动回滚用户文件或历史。
3. **建分支明确基线与切换**：核对任务基线和分支名称，创建并切换；重名报错，不重置同名分支，不创建 main，不在不适合切换的工作区强行执行。
4. **push 目标明确**：只用事先确定的已有远端名，显式推到同名功能分支；不依赖可能指向别处的默认上游，不推 main、不强推、不接收 URL。核对目标分支与提交结果。
5. **作者归属与暂存保护**：提交说明区分编码作者与执行提交的 Agent，代提交不改变作者或独立审核资格。已有无关暂存内容时停止，不自动清空；只提交声明且审核过的内容。同文件贡献无法分清时报告，不猜测归属。

首期沿用正常 git commit 和仓库 hooks，不默认跳过检查。hook 在提交前失败时报告并保留现场；若提交已经产生，返回该 commit 并说明后处理失败，不再创建第二次提交。专门 hooks 隔离与策略系统留后，基本结果核实不延期。

## 7. 方案取舍与扩展空间

| 方向 | 当前取舍及理由 |
|---|---|
| 原完整统一提交服务 | 收敛为共用模块及必要接入；多进程协调和通用授权超出当前单功能流程，保留五个小检查。 |
| 各 Agent 各自拼 Git 命令 | 不采用；检查容易重复，且不能解决环境权限差异。共用封装即可。 |
| HTTP 服务、通用凭证与权限平台 | 首期不建设，避免把减少手工 Git 扩成通用平台。 |
| 串行锁、独立 worktree | 留后扩展，首期依赖单功能独占工作区。 |
| 首期 main 合入 | 不实现，保持用户明确请求的独立边界。 |

扩展只留两处：

- **任务上下文解析**：接口带 task_id，目录由“任务 → 工作目录”解析；首期可以关联既有对话目录。将来 worktree 改解析结果，Agent 侧上述业务接口保持不变。
- **唯一执行入口**：Git 从共用模块同一个执行函数出去，将来串行锁包住执行函数，不让 Agent 感知锁细节。扩展时仍需验证目录、会话等集成影响，不宣称 worktree 只需加一个命令。

## 8. 实施前少量待决项与留后事项

| 首期实施前需明确 | 最小内容 |
|---|---|
| review 记录存放位置 | 如何读取非作者通过记录、表示受检文件差异和写回 commit_id，不建设完整审批平台 |
| 有权限的执行入口 | 模块在哪里运行、三个 Agent 如何接入，正常配置 .git 写权限和远端认证，不绕过沙箱 |
| 固定远端名 | 在任务仓库中选定已有远端，仅显式推到同名功能分支，不接收 URL |
| 建分支基线 | 明确任务起始分支及 commit，记录创建切换结果，不猜测基线 |

原设计的 worktree、跨进程锁、通用身份凭证、独立内容快照机制、完整崩溃恢复状态机、专门 hooks 隔离与策略系统均为**留后、扩展空间**，不再列为首期必做或待决门槛。第6节受检内容核对、失败分阶段及未知结果先查询仍属首期基本行为。

## 9. 验收计划与实际结果

先在隔离临时仓库和本地 bare 远端验证，再按明确授权验证真实接入：

- Codex、DeepSeek Harness、Grok 三个 Agent 能使用配置好的入口，不把只读 Git 成功等同写权限验证。
- 从明确基线创建并切换功能分支；main 名称、重名、不适合切换的工作区被拒绝，不丢改动。
- 有效非作者 review 后准确提交并写回 commit_id；缺审核、自填通过或受检内容变化时拒绝。
- 声明文件准确提交，保护无关暂存内容，区分作者与提交执行者。
- 普通 push 只更新固定已有远端的同名功能分支；不开放 push main、force、删除分支及 URL 输入。
- commit 成功而 push 失败时返回原提交、仅补推送；超时先核实，hook 失败不盲目重复提交，现场可检查。
- 首期不暴露可执行的 main 合入能力，不声称支持多功能并发。

上述清单保留为验收目标；实际已执行范围如下，未覆盖的目标不能算通过。停用工具不应回滚用户已有提交或工作区改动。

### entry-2170 模块实现与接入契约（2026-11-01）

- 新增 `git_automation.py`：`GitAutomation(resolve_task, reviews)` 提供两个操作和只读的 `content(task_id, files)` 辅助函数。所有 Git 进程经 `_git`，未实现 main 合入、锁、worktree 或凭证平台。任务范围首期收紧为 `feature/` 分支；符号链接、子模块和目录文件清单不支持，遇到即拒绝。
- 任务由宿主的 `resolve_task(task_id)` 返回不可变 `GitTask(directory, branch, base_commit, remote, author, executor)`；基线须为完整 commit ID，remote 须是已有远端名。拒绝多个推送地址或查询地址与推送地址不同的配置，确保结果查询对应实际推送目标。
- 最小记录采用宿主管理的 `JsonReviewStore`，每任务一个 UTF-8 JSON，目录必须在任务仓库外。宿主须以文件访问权限保护 reviewer 记录；普通调用者不能通过操作参数注册任务或批准自己。尚未接入生产工作台或 MCP，也未配置实际执行权限，不能据此宣布 Agent 已可自动提交。
- 记录字段：`task_id`、`branch`、`base_commit`、`author`、非作者 `reviewer`、`approved=true`、`content`。reviewer 可调用只读 content 辅助函数取得受检文件的 Git blob ID 和模式（删除为 null），核对后由宿主保存批准；辅助函数自身不构成批准。提交前比对工作文件和 index，提交后比对树及父提交。新建、二进制、删除覆盖在测试内。
- 执行在同一记录中写入 `operation`，含请求摘要、预期树、提交信息、`commit_id`、`push_status`。这是防止一次任务重复提交的最小结果记录，不是完整崩溃恢复平台。后续同参数调用先核实本地提交并查询远端，只补推原提交；不同参数拒绝。提交未确认或树不符时保留现场，由宿主检查并处理记录后再继续，不自动 reset 或清空 index。
- 沿用正常 commit/hooks；hook 改写了受检树时可能已产生本地提交，模块报告该提交与错误，不推送、不回滚。子进程超时和复杂 hook 后代进程的完整生命周期隔离未实现，未知结果须检查，不能声称绝对并发或崩溃隔离。
- 作者验证：`python -m py_compile git_automation.py test_git_automation.py` 通过；`python -B -m unittest test_git_automation -v` 15项通过（37.177秒）。真实 Git init/commit/push 只发生在临时仓库与本地 bare 远端；响应丢失通过包裹真实操作后注入超时验证，不作为真实网络超时实验。
- 完整本地回归：`python -B -m unittest discover` 共207项，206通过、1跳过、0失败（65.445秒，退出码0）；跳过项不计入通过。日志含既有故障注入诊断，无失败用例。语法与 `git diff --check` 通过，不作为真实接入验收。
- 初轮11项有1项删除文件错误，修正暂存删除后从基线确认文件身份后复跑11项通过，再扩展为上述15项。生产仓库未执行 Git 写操作；真实 .git 写权限、真实远端、三客户端接入以及双非作者审核尚未验收。固定远端及基线由宿主显式配置，不猜测生产值。
